# VS-03 — Leave Types & Leave Balance

## Summary
VS-03 introduces the leave configuration and balance capability required before an employee can actually apply for leave.
An Admin can create and manage leave types and assign leave allocations to active employees; employees can view their available leave balance.

This slice builds directly on VS-02's Employee capability and provides the foundation for VS-04 — Apply for Leave.

---

```

      │
      ▼
```

### Business Context
An organization needs to define different types of leave and determine how many days each employee has available.
Example:
- Casual Leave → 12 days
- Sick Leave   → 10 days
- Earned Leave → 15 days

---

## 2. Slice Goal
The goal is to provide:
1. Leave type management (Create, Edit, Activate/Deactivate, List)
2. Employee leave allocation (Assign allocation to active employees)
3. Leave balance calculation (`Remaining = Allocated - Used`)
4. Employee balance viewing (`/my/leave-balances`)

---

## 3. Success Criteria
VS-03 is complete when:
- Admin can create a leave type.
- Admin can edit a leave type.
- Admin can activate/deactivate a leave type.
- Admin can assign leave allocation to an employee.
- Employee can view their leave balance.
- Remaining balance is calculated correctly.
- Inactive employees cannot receive new allocations.
- Duplicate leave-type names/codes are rejected.
- Relevant tests pass.

## 5. Atomic Requirements
- **AR-01 — Create Leave Type**: Admin shall be able to create a leave type.
- **AR-02 — View Leave Types**: Admin shall be able to view configured leave types.
- **AR-03 — Edit Leave Type**: Admin shall be able to modify leave type information.
- **AR-04 — Deactivate Leave Type**: Admin shall be able to deactivate a leave type without deleting historical data.
- **AR-05 — Allocate Leave**: Admin shall be able to assign an allocation to an employee.
- **AR-06 — View Balance**: Employee shall be able to view their available leave balance.
- **AR-07 — Calculate Remaining Balance**: The system shall calculate `Remaining = Allocated - Used`.
- **AR-08 — Prevent Invalid Allocation**: The system shall reject invalid allocations such as negative days.
- **AR-09 — Employee Validation**: Leave allocation shall reference an existing employee.
- **AR-10 — Leave Type Validation**: Leave balance shall reference an existing leave type.

---

## 6. Data Model

### 6.1 LeaveType
`leave_types`
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `code` TEXT UNIQUE NOT NULL
- `name` TEXT NOT NULL
- `description` TEXT
- `default_allocation` INTEGER NOT NULL DEFAULT 0
- `status` TEXT NOT NULL DEFAULT 'active' ('active' | 'inactive')
- `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP
- `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP

### 6.2 LeaveBalance
`leave_balances`
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `employee_id` INTEGER NOT NULL (FK -> `employees(id)`)
- `leave_type_id` INTEGER NOT NULL (FK -> `leave_types(id)`)
- `allocated_days` INTEGER NOT NULL DEFAULT 0
- `used_days` INTEGER NOT NULL DEFAULT 0
- `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP
- `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP
- `UNIQUE(employee_id, leave_type_id)`

---

## 7. Business Rules
- **BR-01 — Admin Management**: Only Admin can create or modify leave types or assign allocations.
- **BR-02 — Positive Allocation**: `allocated_days >= 0` (negative days are invalid).
- **BR-03 — Used Days Cannot Be Negative**: `used_days >= 0`.
- **BR-04 — Used Days Cannot Exceed Allocation**: `used_days <= allocated_days`.
- **BR-05 — Remaining Balance**: `remaining = allocated - used`.
- **BR-06 — Unique Leave Type Code**: Two active leave types cannot have the same code.
- **BR-07 — Inactive Leave Type**: An inactive leave type cannot be used for new allocations.
- **BR-08 — Inactive Employee**: An inactive employee cannot receive a new leave allocation.
- **BR-09 — Historical Data**: Deactivating a leave type must not delete existing balances.

## 8. Routes
### Leave Types
- `GET /leave-types` — List leave types (Admin)
- `GET /leave-types/new` — Create form (Admin)
- `POST /leave-types` — Create leave type (Admin)
- `GET /leave-types/{id}/edit` — Edit form (Admin)
- `POST /leave-types/{id}` — Update leave type (Admin)
- `POST /leave-types/{id}/activate` — Activate leave type (Admin)
- `POST /leave-types/{id}/deactivate` — Deactivate leave type (Admin)

### Leave Balances
- `GET /leave-balances` — Admin balance list (Admin)
- `GET /leave-balances/new` — Allocation form (Admin)
- `POST /leave-balances` — Create allocation (Admin)
- `GET /my/leave-balances` — Employee's own balances (Authenticated Employee/Admin/Manager)

## 9. Acceptance Tests (AT-01 to AT-08)
- **AT-01 — Create Leave Type**: Admin creates "Casual Leave" (CL, 12 days) -> Created and displayed in list.
- **AT-02 — Duplicate Code**: Creating another leave type with code CL -> Rejection error.
- **AT-03 — Invalid Allocation**: Assigning -5 days -> Rejected with validation error.
- **AT-04 — Assign Balance**: Allocating 12 days to active employee Rahul for active Casual Leave -> Allocated=12, Used=0, Remaining=12.
- **AT-05 — View Balance**: Rahul views `/my/leave-balances` -> Allocated, used, and remaining values displayed.
- **AT-06 — Inactive Employee**: Assigning allocation to inactive employee -> Rejected.
- **AT-07 — Inactive Leave Type**: Assigning inactive leave type -> Rejected.
- **AT-08 — Remaining Calculation**: Allocated=12, Used=4 -> Remaining=8.

## 10. Handoff to VS-04
VS-04 requires `GetBalance(employeeID, leaveTypeID)` returning `LeaveBalance` struct with `Allocated`, `Used`, and `Remaining`.
Deduction of leave belongs to VS-04 leave request approval, not VS-03.
