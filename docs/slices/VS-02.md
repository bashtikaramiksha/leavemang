# VS-02 — Employee Management

### Summary

**VS-02** builds the first real business capability on top of VS-01:

> **An Admin can create, view, edit, activate, and deactivate employees, while authenticated users can access only the employee information permitted by their role.**

VS-01 already provides authentication, sessions, and roles. **VS-02 must reuse those capabilities rather than rebuilding them.**

---

# 1. Slice Context

```text
VS-01
Authentication
     │
     │ authenticated user
     │ + role
     ▼
VS-02
Employee Management
     │
     ├── Create Employee
     ├── View Employees
     ├── Edit Employee
     ├── Activate Employee
     └── Deactivate Employee
     │
     ▼
VS-03
Leave Types & Leave Balance
```

### Business Context

The organization needs a central employee directory because future leave functionality must know:
* Who the employee is
* Which employee is making a request
* Which manager can review requests
* Whether an employee is active
* What role the user has

---

# 2. Slice Goal

### Primary Goal

Allow an **Admin** to manage the organization's employee records.

### Secondary Goal

Provide a reliable employee identity that later slices can reference.

```text
Employee
   │
   ├── Leave Balance
   │
   ├── Leave Request
   │
   └── Approval History
```

---

# 3. Actors

| Actor    | Access                                |
| -------- | ------------------------------------- |
| Admin    | Full employee management              |
| Manager  | View permitted employee information   |
| Employee | View own employee information         |
| System   | Enforces authorization and validation |

---

# 4. Atomic Requirements

* **AR-01 — Employee Creation:** Admin shall be able to create an employee.
* **AR-02 — Employee List:** Admin shall be able to view a list of employees.
* **AR-03 — Employee Details:** Authorized users shall be able to view employee details.
* **AR-04 — Employee Editing:** Admin shall be able to edit employee information.
* **AR-05 — Employee Activation:** Admin shall be able to activate an inactive employee.
* **AR-06 — Employee Deactivation:** Admin shall be able to deactivate an active employee.
* **AR-07 — Unique Email:** Employee email addresses shall be unique.
* **AR-08 — Required Information:** The system shall validate required employee fields before creation.
* **AR-09 — Role Assignment:** Admin shall be able to assign an application role to the employee/user account where applicable.
* **AR-10 — Authorization:** Only authorized users shall access employee-management operations.
