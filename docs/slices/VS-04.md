# VS-04 — Apply for Leave

## Summary
VS-04 builds the first complete employee leave workflow.
An authenticated employee can select an active leave type, enter leave dates and a reason, have the request validated against their available balance and existing requests, and submit a leave request with `Pending` status.
This slice consumes the capabilities created by VS-02 and VS-03 and produces the leave request that VS-05 will review.

## Context Map
VS-01 (Authentication) -> VS-02 (Employee Management) -> VS-03 (Leave Types & Balance) -> VS-04 (Apply for Leave) -> VS-05 (Manager Approval)

## Slice Goal
Allow an employee to submit a valid leave request.

## Success Criteria
VS-04 is complete when:
1. Employee can open the leave application form (`/my/leave-requests/new`).
2. Employee can select an active leave type.
3. Employee can select valid dates.
4. System calculates requested leave days (`to_date - from_date + 1`).
5. Employee can enter a reason.
6. System validates available balance (`Requested Days <= Remaining Days`).
7. System detects conflicting/overlapping leave requests (for `Pending` or `Approved` requests).
8. Valid request is stored as `Pending`.
9. Invalid request is rejected with a useful error message.
10. Employee can see their newly submitted request (`/my/leave-requests` and `/my/leave-requests/{id}`).
11. Tests pass.

## Data Model (LeaveRequest)
- `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
- `employee_id` (INTEGER NOT NULL, FK to employees)
- `leave_type_id` (INTEGER NOT NULL, FK to leave_types)
- `from_date` (TEXT NOT NULL, YYYY-MM-DD)
- `to_date` (TEXT NOT NULL, YYYY-MM-DD)
- `days` (INTEGER NOT NULL)
- `reason` (TEXT NOT NULL)
- `status` (TEXT NOT NULL DEFAULT 'Pending')
- `created_at` (DATETIME DEFAULT CURRENT_TIMESTAMP)
- `updated_at` (DATETIME DEFAULT CURRENT_TIMESTAMP)
- `reviewed_by` (INTEGER NULL, FK to users)
- `reviewed_at` (DATETIME NULL)

## Business Rules
- **BR-01**: Authentication required (employee derived from session).
- **BR-02**: Active employee required (`status == 'active'`).
- **BR-03**: Active leave type required (`status == 'active'`).
- **BR-04**: Valid date range (`from_date <= to_date`).
- **BR-05**: Days calculation = `(to_date - from_date) + 1` calendar days.
- **BR-06**: Balance rule: `Requested Days <= Remaining Days` (`Allocated - Used`). Note: balance is NOT deducted upon submission (deduction happens on manager approval in VS-05).
- **BR-07**: Reason required (non-empty).
- **BR-08**: Overlap detection: Prevent new request if it overlaps an existing `Pending` or `Approved` request for the same employee. `Rejected` requests do not block. Overlap formula: `ExistingStart <= NewEnd AND ExistingEnd >= NewStart`.

## Routes
- `GET /my/leave-requests`: Employee request list
- `GET /my/leave-requests/new`: Application form
- `POST /my/leave-requests`: Submit request
- `GET /my/leave-requests/{id}`: Request details

## Handoff to VS-05
VS-04 stores pending requests and provides `ListPending()` / `GetByID()` in the repository/service layer so VS-05 (Manager Approval) can query pending requests and execute approve/reject actions.
